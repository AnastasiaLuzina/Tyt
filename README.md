# «Тут» — сервис обмена вещами в общежитии (v4)

**«Тут»** — это веб-приложение для студентов, позволяющее отдавать и забирать ненужные вещи внутри своего общежития. Проект сочетает удобный интерфейс (React) с бэкендом на Express, Telegram-ботом для анонимного общения, пагинацией, поиском, редактированием объявлений, загрузкой аватар, **интеграционными тестами** и **оркестрацией через Kubernetes**.

---

## 📦 Функциональность (v4)

- Публикация объявлений с фото.
- Категоризация вещей (книги, одежда, техника и др.).
- Просмотр ленты активных объявлений с **пагинацией** и **поиском** по названию и описанию.
- Фильтр по категориям.
- Возможность оставить заявку на понравившуюся вещь.
- Автоматическое создание диалога в Telegram между владельцем и заявителем.
- Управление своими объявлениями:
  - просмотр заявок,
  - выбор получателя,
  - **редактирование** (название, описание, категория, фото),
  - **изменение статуса** (активно / зарезервировано / завершено).
- Профиль пользователя с **загрузкой аватарки**, «котодомом» (интерактивный маскот) и настройками.
- **Верификация через Telegram** с таймером обратного отсчёта и повторной отправкой кода.
- **Документация API** через Swagger UI (`/api-docs`).
- **Интеграционные тесты API** (Jest + Supertest), запускаемые локально и в CI.
- **Оркестрация через Kubernetes** (манифесты для деплоя, сервиса, Ingress, ConfigMap).
- Безопасное хранение токена бота через переменные окружения (`.env`).
- Контейнеризация (Docker + docker-compose) и автоматическая сборка/публикация образа в GitHub Container Registry (GHCR) через GitHub Actions с прогоном тестов перед сборкой.

## 🚀 Запуск проекта

### Обычный запуск (без Docker)

1. **Клонируйте репозиторий**
   ```bash
   git clone https://github.com/ваш-аккаунт/Tyt.git
   cd Tyt
   ```

2. **Установите зависимости**
   ```bash
   npm install
   ```

3. **Создайте файл `.env`** (скопируйте `.env.example`):
   ```env
   BOT_TOKEN=ваш_токен_от_BotFather
   PORT=8001
   BOT_USERNAME=TytShare_BoT
   SITE_URL=http://localhost:3000   # для кнопки "Сайт" в боте
   ```

4. **Запустите сервер и клиент**
   - В одном терминале: `npm run server` (запускает `backend/server.js`)
   - В другом: `npm start` (запускает React-клиент)
   - Или одной командой: `npm run dev` (если установлен concurrently)

5. **Заполните базу тестовыми данными** (опционально):
   ```bash
   node backend/seed.js   # если seed.js лежит в backend/
   ```

### 🐳 Запуск через Docker (рекомендуется для продакшена)

1. **Установите Docker и Docker Compose.**
2. **Скопируйте `.env.example` в `.env`** и заполните реальными данными.
3. **Соберите и запустите контейнер:**
   ```bash
   docker-compose up -d
   ```
4. **Проверьте логи:**
   ```bash
   docker-compose logs -f
   ```
5. Откройте браузер на `http://localhost:8001` — приложение готово.

## 🧪 Тестирование

### Локальный запуск тестов

```bash
npm test
```

Тесты используют in-memory SQLite, поэтому они не затрагивают вашу основную базу данных. Запускаются интеграционные тесты API (Jest + Supertest), проверяющие:

- регистрацию пользователя,
- создание объявления (с фото),
- получение списка с пагинацией,
- создание заявки,
- редактирование объявления,
- изменение статуса.

### Тесты в CI

При каждом пуше в `main` и в PR автоматически запускаются тесты (через GitHub Actions). Если тесты падают, сборка Docker-образа не выполняется — это гарантирует, что в продакшн попадает только протестированный код.

## ☸️ Оркестрация (Kubernetes)

### Предварительные требования

- Установленный `kubectl` и доступ к кластеру Kubernetes (локальный Minikube, облачный кластер или K3s на VPS).
- Настроенный доступ к GitHub Container Registry (GHCR) для скачивания образа (создайте `regcred`, если требуется).

### Шаги по развёртыванию

1. **Создайте секрет с токеном бота** (замените `ваш_токен`):
   ```bash
   kubectl create secret generic tyt-secrets --from-literal=bot-token=ваш_токен
   ```

2. **Примените манифесты** (из папки `k8s/`):
   ```bash
   kubectl apply -k k8s/
   ```

3. **Проверьте статус**:
   ```bash
   kubectl get pods
   kubectl get svc
   kubectl get ingress   # если используете Ingress
   ```

4. **(Опционально) Настройте Ingress**, указав свой домен в `k8s/ingress.yaml` и убедившись, что у вас установлен Ingress-контроллер.

После этого приложение будет доступно по адресу вашего кластера (или через Ingress по домену).

## ⚙️ CI/CD (GitHub Actions)

В папке `.github/workflows/` лежит файл `docker-publish.yml`. При пуше в `main` и в PR автоматически:

1. Запускаются тесты (job `test`).
2. Если тесты проходят, собирается Docker-образ.
3. Образ публикуется в GitHub Container Registry (GHCR) с тегами `latest` и хешем коммита.
4. (Опционально) Деплоится на VPS через SSH (если настроены секреты).

🧩 Процесс разработки (GitFlow)
Мы используем GitFlow для управления версиями:

Ветка main – всегда стабильный продакшн-релиз.

Ветка develop – основная ветка для интеграции фич.

Все новые возможности разрабатываются в feature-ветках от develop.

После завершения работы открывается Pull Request (PR) в develop с описанием изменений.

PR проходит автоматические тесты (CI) и требует как минимум одного аппрува от ревьювера.

Релизы формируются через PR из develop в main (по расписанию или по тегам).

Запрещено пушить напрямую в main или develop.

Подробнее – см. CONTRIBUTING.md и шаблон PR в .github/pull_request_template.md.

🗄️ Миграции базы данных
Для управления схемой SQLite используется простой миграционный скрипт без внешних зависимостей.

Все изменения схемы хранятся в папке backend/migrations/ в виде .sql-файлов.

Каждая миграция применяется один раз (отслеживается в таблице migrations).

Перед запуском приложения выполните:

bash
npm run migrate
Это создаст все необходимые таблицы (пользователи, объявления, заявки) и подготовит БД к работе.

Если вы добавляете новую миграцию, просто положите новый .sql-файл в backend/migrations/ и запустите скрипт повторно – он применит только новые файлы.

🧪 Тестирование и покрытие
Интеграционные тесты (Jest + Supertest) покрывают основные сценарии:

регистрация и аутентификация,

создание, редактирование, получение объявлений с пагинацией,

создание заявок и изменение статуса,

загрузка аватарки,

работа с пользовательским профилем.

Запуск:

bash

Тесты используют in-memory SQLite, поэтому не затрагивают вашу реальную базу. В CI они прогоняются перед каждой сборкой Docker-образа, что гарантирует, что в продакшн попадает только протестированный код.

Покрытие расширяется – новые тесты добавляются вместе с новой функциональностью.
